# 患者状态流转规则

- 患者流转是状态机，不是普通 CRUD。
- 不要默认修改状态码的含义。
- 不要默认改变状态之间的转换条件。
- 涉及等待区、排队、叫号、准备区、手术中、恢复区、出院的逻辑，都要按状态流转问题处理。
- State 6（已准备）到 State 7（手术中）当前按"患者和设备配对"理解。
- 修改状态流转前，先确认是否影响预约、叫号、区域流转、大屏展示、ARS 汇总。
- `PatientStatusServiceImpl` 属于高风险模块，只有在任务明确要求时才应修改。
- `SuperPatient (surgeryId=0)` 是历史演示逻辑，不要把它当成正常业务模式继续扩散。
- 如果状态流转逻辑与接口文档、业务流程描述不一致，先标记风险，不要先重构。
