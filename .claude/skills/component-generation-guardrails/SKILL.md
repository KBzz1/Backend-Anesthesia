# Component Generation Guardrails

## 设计哲学（必须遵守）

系统采用三层结构：

- command：用户入口与工作流编排
- agent：顺序执行工作流，使用预加载 skill
- skill：承载详细规则、判断逻辑或执行步骤

这样设计的原因：

1. 控制复杂度  
   将“入口、编排、规则”分离，避免单个组件变得不可维护

2. 提高复用性  
   skill 可以被多个 agent 或 command 复用  
   agent 可以被多个 command 复用

3. 提高可控性  
   将规则集中在 skill 中，避免隐式逻辑分散在各处

4. 降低错误风险  
   避免在 command 或 agent 中重复或遗漏关键逻辑

---

## 职责边界（不可违反）

三类组件必须严格分层，**不可重叠职责**

### command 的职责

command 只负责：

- 接收用户输入
- 补充必要信息
- 选择执行路径（直接 / agent / skill）
- 触发执行
- 展示结果与确认

command 不得：

- 承载可复用逻辑
- 写复杂判断规则
- 实现完整工作流
- 重复 skill 或 agent 中的内容

---

### agent 的职责

agent 只负责：

- 按顺序执行任务
- 调用预加载 skill
- 读取上下文（如仓库结构）
- 返回结果

agent 不得：

- 重写 skill 中的详细规则
- 成为规则存储中心
- 承载复杂业务逻辑说明
- 混合架构决策与生成细节

agent 应保持极简，只表达：

- 调用哪个 skill
- 做什么检查
- 返回什么结果

---

### skill 的职责

skill 负责：

- 详细规则
- 判断逻辑
- 执行步骤
- 生成约束

对于预加载 skill：

- 使用 policy / SOP 风格
- 直接写规则，不写说明性内容
- 聚焦单一职责

skill 不得：

- 承担用户交互
- 承担工作流编排
- 重复 command 或 agent 的职责

---

## 核心原则

### 1. 最小生成原则

始终生成“最小满足需求”的结构：

- 不额外创建组件
- 不预先扩展未来需求
- 不创建“可能会用到”的 agent 或 skill

---

### 2. 职责单一原则

每个组件只做一件事：

- command 不做 agent 的事
- agent 不做 skill 的事
- skill 不做 command 的事

---

### 3. 不重复原则

不得出现：

- 同一逻辑在多个组件中重复
- 同一职责多个组件实现
- skill 与 agent 重复规则

---

### 4. 复用优先原则

在生成前必须检查：

- `.claude/commands/`
- `.claude/agents/`
- `.claude/skills/`

并遵守：

- 优先复用已有组件
- 优先扩展已有组件
- 避免创建语义重复组件

---

### 5. 显式确认原则

在创建以下内容前必须确认：

- agent
- skill
- 多组件结构

未确认时：

- 只输出建议与计划
- 不执行创建

---

## 生成约束

生成时必须：

- 明确列出所有将创建的文件
- 说明每个文件的职责
- 说明为什么需要这些文件
- 说明为什么不需要更多组件

不得：

- 隐式创建额外组件
- 自动扩展 scope
- 默认生成完整体系（command + agent + skill）

---

## 冲突处理规则

遇到冲突时：

- 命名冲突 → 调整命名
- 职责冲突 → 优先复用或合并
- 结构冲突 → 选择更小、更简单的方案

不得：

- 创建平行重复组件
- 保留冲突结构不处理

---

## 输出要求

必须输出：

- 推荐结构
- 最小生成文件清单
- 每个文件的职责说明
- 使用的设计原则
- 假设与风险
